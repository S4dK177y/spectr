# Security Policy — Spectr

**Spectr** обрабатывает чувствительные персональные данные о настроении и самочувствии. Безопасность и приватность заложены в архитектуру с первого дня.

## Принципы приватности

1. **Локальный режим по умолчанию:** вы можете пользоваться приложением полностью офлайн без создания аккаунта. Данные не покидают ваше устройство.
2. **Ноль аналитики и трекеров:** в приложении нет рекламных SDK, аналитики поведения и скрытой телеметрии.
3. **Сквозное шифрование (E2EE) для облачной синхронизации:**
   - Используется единый пароль пользователя, который **никогда** не отправляется на сервер в открытом виде.
   - На устройстве из пароля с помощью `PBKDF2-HMAC-SHA256` (600 000 итераций) и `HKDF-SHA256` раздельно выводятся секрет аутентификации и ключ шифрования ключей (`KEK`).
   - Все записи дневника, отрезки сна, отметки момента и шкалы шифруются локально алгоритмом `AES-256-GCM` со случайным 256-битным ключом данных (`DEK`), уникальным 96-битным `IV` и аутентифицированными метаданными (`AAD = userId:entityType:recordId`).
   - В базе данных Supabase хранятся только зашифрованный `ciphertext`, `iv` и минимальные технические метаданные синхронизации (`id`, `user_id`, `entity_type`, `updated_at`, `deleted_at`).
   - Доступ к строкам на сервере дополнительно ограничен строгими политиками PostgreSQL Row-Level Security (`RLS`).
4. **Защита на устройстве:**
   - Кэшированный `DEK` защищён стандартным `AndroidKeyStore`.
   - Опциональная блокировка приложения по биометрии/PIN (`BiometricPrompt`) и запрет превью в списке недавних приложений (`FLAG_SECURE`).
   - Нейтральные тексты уведомлений на экране блокировки.
